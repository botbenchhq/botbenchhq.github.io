What works today, and what does not yet.

Each line has a state and a place in the code or an issue. Available means it works in the current code. Early means it works in a first, limited form, or is in the code and not yet confirmed on a real device. Planned means it is not built.

  • AvailableAgentssrc/drivers/claude-code.ts

    Claude Code plans and builds

    One task at a time, each in its own copy and branch, under your own sign-in.

  • AvailableAgentssrc/drivers/codex.ts

    Codex builds

    Chosen per task or run once Botbench's check finds that your Codex can build. It works in its own sandbox, in the task's copy, with no network.

  • AvailableAgentssrc/engine/review.ts

    Review by another vendor's agent

    Codex, Grok or Antigravity reads the change and is asked to say what it checked. With concerns, the builder makes rounds of fixes.

  • AvailableAgentsweb/src/screens/turn.tsx

    Chat with any agent, or several at once

    Ask Claude Code, Codex, Grok or Antigravity outside a repository, and compare their answers.

  • AvailableAgentssrc/engine/handoff.ts

    Move a task to another agent

    From Claude Code to Codex or back while it is being built. The work so far is committed, and the other agent carries on in the same copy and branch.

  • AvailableAgentssrc/engine/usage-limit.ts

    Wait out a usage limit, or switch

    A task waits and starts again at the reset time, or moves to the next agent on your list.

  • AvailableControlsrc/approvals/

    Approval cards

    An action that reaches outside the task's copy waits for your answer, on the Mac or your phone. A short list of dangerous commands always asks.

  • AvailableControlsrc/engine/modes.ts

    Three modes per run

    Manual, semi-autonomous and fully autonomous. The safety rules are the same in every mode.

  • AvailableControlsrc/confinement.ts

    Confined commands

    Commands run in the macOS sandbox, kept away from your sign-ins and the network. Not a virtual machine or a container.

  • AvailableControlsrc/approvals/question.ts

    An agent can ask you a question

    A card with lettered choices. Your answer goes back as text and allows nothing to run.

  • AvailableWorksrc/engine/stations.ts

    Checks and setup per repository

    Your own commands, run after the work is committed, with their output kept.

  • AvailableWorksrc/engine/delivery.ts

    A pull request for an accepted task

    Opened with your own git and gh, only when you chose it for the run. Never the default branch, never by force, never merged.

  • AvailableWorksrc/engine/intake.ts

    A run from a GitHub issue

    Read with your own gh and treated as outside text: it always waits for plan approval and is never fully autonomous.

  • AvailableWorksrc/engine/watch.ts

    Watch a repository for labelled issues

    Each is listed as a proposal with Start and Dismiss. Nothing starts by itself.

  • AvailableTeamsrc/engine/peers.ts

    See other workbenches' work

    A read-only view of their open pull requests and pushed branches on the same remote, with a warning when one covers your issue or your files.

  • AvailableTeamsrc/engine/claims.ts

    Claim an issue

    Off by default. The remote takes only the first claim; the later run stops and opens no pull request.

  • AvailableTeamsrc/engine/combined.ts

    Check together

    Merge your ready task with a teammate's open pull request in a temporary copy and run the repository's checks on the merge.

  • EarlyTeamdocs/pairing.md

    Pair with one other workbench

    An invite that works once, fingerprints you both compare. One pairing per installation. Tested on one Mac over loopback, not across two Macs.

  • EarlyTeamsrc/peers/conversation.ts

    Questions and answers between paired workbenches

    You approve every message that leaves and decide about every message that arrives. A thread stops at 3 round trips.

  • EarlyControldocs/adr/0009-container-execution.md

    Run a repository's commands in a container

    Set per repository: one Docker container per task, from an image already on your Mac, holding only the task's copy and no network. Claude Code itself stays on your Mac. It cannot be combined with allowed hosts, and a task Codex builds is refused there.

  • EarlyWorksrc/push.ts

    Home Screen app and notifications on a phone

    In the code, not confirmed on a real iPhone.

  • PlannedTeamIssue #154

    More kinds of message between workbenches

    Interface proposals, counters, accepts, blockers, review requests and verdicts; pairing across two Macs; more than one pairing.

  • PlannedTeamIssue #172

    Work that depends on a teammate's work

    Including two changes to different files that must meet one shared contract.

  • PlannedWorkIssue #174

    A shorter first run

    Today it takes about ten minutes from cloning to a first branch.

  • PlannedTeamdocs/product/positioning-concept.md

    Beyond coding

    Coding is where Botbench starts. Nothing beyond it is built.

The main capabilities, taken from the README's "What works today", "Configure a repository" and "Where it is going". The code is the authority; where this page and the code differ, the code is right.
